# 用户体验修复与验证

本轮针对此前列出的用户体验问题修复，没有改变 Web / Desktop 使用后端主存储、Mobile 使用本地主存储的边界。此前数据与部署审查的记录仍保留在 `audit-remediation-2026-08-31.md`，本记录不替代其中尚未进行的原生窗口或部署验收。

## 修复结果

| 问题 | 修复 |
| --- | --- |
| 窄窗口中的设置内容被侧栏挤压 | 设置改用横向分组导航；表单按可用内容宽度排列；底部按钮和长内容保持可操作。桌面配置最小窗口为 360 × 560。 |
| 900px 左右的正文未居中 | 编辑区与列表使用同一宽度限制并居中。 |
| 保存或图片上传失败没有反馈 | 显示错误，保留正文和附件；保存过程中锁定编辑、格式快捷键和粘贴；无法读取后端时说明原因并提供重试。 |
| 搜索旧响应覆盖新结果，筛选不一致 | 搜索请求按最新一轮生效，清空搜索会让旧请求失效；搜索与日期、标签取交集；加载、没有匹配结果和真正空库分别呈现。回收站读取也避免旧请求覆盖新状态。 |
| 删除后难以恢复，永久操作提示不准确 | 删除后提供撤销，导航增加回收站；笔记操作按钮常显并增大；永久删除、清空、重置、恢复备份使用应用内确认，明确后端与当前设备的影响范围。 |
| 编辑模式和快捷键文案误导 | 明确区分富文本与 Markdown 源码，设置支持默认模式；Ctrl+K 在编辑器内插入链接，在编辑器外聚焦搜索。插入链接保留原选区。 |
| 文字对比度不足、深色错误通知难读 | 调整三套主题的明暗配色，按钮使用匹配的前景色；错误和信息通知不再使用固定浅色背景。 |
| 主要筛选只能使用鼠标 | 日历、热力图、标签和同步选项支持键盘操作；补充选中状态、控件名称与焦点提示。 |
| 假统计、随机重复、笔记越多页面越慢 | 记录天数按实际日期计算；随机排除当前笔记，只有一条时禁用换篇；列表每页最多 40 条，可直达任意页，编辑中翻页先确认。 |
| 初始化重复读取、Windows 启动失败 | 去掉重复刷新；同步仅在实际完成后刷新；两个 PowerShell 入口使用 UTF-8 BOM，批处理优先使用 PowerShell 7，也兼容 Windows PowerShell。 |

## 已执行的验证

`npm run test:unit` 执行全部 25 个测试文件，全部通过，其中包括新增 `uxState.spec.ts`。`npm run build` 的 Vue / TypeScript 检查与前端构建通过，没有生成桌面安装包。

`npm run test:ux` 使用 Windows 上的 Chrome 和隔离浏览器上下文执行交互回归，覆盖初次加载、搜索乱序、组合筛选、键盘操作、随机切换、真实统计、保存失败与输入锁定、删除撤销、链接选区、图片暂存和附件上传失败、窄窗口、主题对比度、千条笔记分页及编辑保护、断线恢复。设置在 900 × 700、800 × 600、720 × 600、360 × 560 下检查；此前还检查了 360 × 640。

三套主题各自的明暗模式中，正文、辅助文字、强调色、按钮文字以及错误/信息通知的所测组合均达到 4.5:1 对比度。浏览器回归没有未处理的页面异常。截图另存于 `D:\Tools\Temp\bemo-ux-fix-20260831\screenshots`，已人工检查窄窗口和深色通知。

Windows PowerShell 的两个启动脚本解析通过，实际启动成功；`start-dev.bat` 也实际启动成功。测试服务使用 D 盘隔离数据目录，关闭启动任务后确认其前后端端口均已释放。

浏览器回归中的笔记接口及失败场景使用受控测试数据。它验证界面与状态处理，不冒充原生 Tauri 窗口、Docker 或手机设备验收；本轮没有执行这些额外验收，也没有使用个人笔记数据库。

## 复现

先用项目启动脚本启动开发服务，数据目录应指向测试目录。随后在 `frontend` 中执行：

```powershell
npm run test:unit
npm run build
$env:BEMO_PLAYWRIGHT_MODULE = 'D:\Tools\npm-global\node_modules\playwright'
$env:BEMO_UX_BASE_URL = 'http://127.0.0.1:5173'
$env:BEMO_UX_OUTPUT_DIR = 'D:\Tools\Temp\bemo-ux-fix-20260831\screenshots'
npm run test:ux
```

浏览器测试复用已有 Playwright 和 Chrome，不会自动下载依赖；如果 Playwright 安装在别处，修改对应环境变量即可。测试脚本通过开发服务器加载当前页面使用的状态模块，因此需要开发服务，不适用于直接对生产站点运行。
